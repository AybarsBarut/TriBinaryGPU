# Status — M2: Unified ISA, Gate-Level ALU, Register File, Single-SM Mini-GPU & Kernel Parity

Date: 2026-11-09. Milestone type: Microarchitecture, Mini-GPU Execution, Kernel Parity & Benchmarking.

## 1. Summary of Delivered Components

- **Unified GPU ISA (`radixlab/isa.py`):**
  - Cross-radix instruction set architecture with 20 instructions:
    - Arithmetic: `ADD`, `SUB`, `NEG`, `MUL`, `MAC`
    - Logic/Relational: `CMP`, `MIN`, `MAX`, `XOR`
    - Shifts & Moves: `SHL`, `SHR`, `MOV`, `LI`
    - Memory: `LD`, `ST` (with base + immediate indexing)
    - Control: `BEQ`, `BLT`, `BRA`, `NOP`, `HALT`
  - Cross-radix assembler supporting symbol labels, relative branch offsets, bracketed memory expressions, and immediate constants.

- **Gate-Level Single-Lane ALU (`radixlab/gen/alu.py`):**
  - Synthesized as a real combinational netlist for binary (`alu_b`) and balanced ternary (`alu_t`).
  - Implements all arithmetic, logic, and shift operations.
  - Subtraction:
    - Binary: Invert `b` with `XOR2` and assert `cin = 1`.
    - Balanced ternary: Invert `b` with single-level `STI` gates and assert `cin = 0` (no borrow/carry chain needed).
  - Shift Right:
    - Binary: Arithmetic shift with MSB sign-extension.
    - Balanced ternary: Shift with neutral `0` insertion in MSB, producing exact division by 3: $(A - d_0)/3$.
  - 100% equivalence verified against golden models across both systems.

- **Multi-Lane Register File (`radixlab/gpu/regfile.py`):**
  - Parametric dual-read, single-write macro model (`macro: true`) with per-access read/write energy and area tracking.
  - Hardwired `R0 = 0` (read-only zero).

- **Single-SM Mini-GPU (`radixlab/gpu/sm.py`):**
  - Scalable SIMT execution engine (tested at 4 and 8 lanes).
  - Warp sequencer with Program Counter, lane active masks, and divergence-tolerant branch resolution.
  - Scratchpad Shared Memory array (`macro: true`).
  - Active execution drives the gate-level ALU netlist for each active lane, tracking cell output switching activity and static timing.

- **Workloads (`workloads/`):**
  - Workload 1: Vector Addition (`vec_add`, $C[i] = A[i] + B[i]$).
  - Workload 2: SAXPY (`saxpy`, $Y[i] = a \cdot X[i] + Y[i]$).
  - Control loop: iterative branch loop verifying branch resolution and register accumulators.
  - Golden models: verified bit-exact identical parity on both GPU-B and GPU-T.

## 2. Experimental Results: GPU-B vs GPU-T on Mini-GPU Workloads

Conducted under ISO-PRECISION:
- Configuration 1: 4 lanes, 8 bits vs 6 trits (9.51 effective bits)
- Configuration 2: 8 lanes, 16 bits vs 11 trits (17.43 effective bits)

Results from `experiments/m2_mini_gpu.yaml`:

| Workload | Config | GPU-B Time (ns) | GPU-T Time (ns) | Time Saving ($r_{\text{time}}$) | Energy Saving ($r_{\text{energy}}$) | Area Saving ($r_{\text{area}}$) | Verdict (Primary) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Vector Add** | 4L (8b vs 6t) | 1.20 ns | 1.38 ns | **-14.6%** | **-1.6%** | **-13.9%** | **REFUTED** |
| **SAXPY** | 4L (8b vs 6t) | 1.68 ns | 1.93 ns | **-14.6%** | **-1.5%** | **-13.9%** | **REFUTED** |
| **Vector Add** | 8L (16b vs 11t)| 2.00 ns | 2.12 ns | **-6.2%** | **+38.8%** | **-3.7%** | **REFUTED** |
| **SAXPY** | 8L (16b vs 11t)| 2.80 ns | 2.98 ns | **-6.2%** | **+51.8%** | **-3.7%** | **REFUTED** |

### Key Scientific Findings:
1. **Clock Cycle and Execution Time:**
   Under the current placeholder cell library assumptions, single-lane gate-level ALU delay is slightly longer for ternary (ripple multiplier and logic muxing at 6 trits yields ~260 ps vs ~225 ps for 8-bit binary). Consequently, GPU-B completes the kernels 6% to 15% faster. Raw speedup for ternary is **REFUTED** at these small widths.
2. **Energy Scaling Advantage at 16-Bit / 11-Trit:**
   While dynamic energy is virtually identical at narrow width (-1.6%), GPU-T achieves a dramatic **+38.8% energy saving on Vector Add** and **+51.8% energy saving on SAXPY** at 16-bit / 11-trit precision. The reduction in total wire toggles and storage transitions across 11 trits (covering >17 effective bits) vs 16 binary bits yields significant energy efficiency during multiplication and memory movement.
3. **Area Convergence:**
   Total GPU area (ALU gate netlist + register file macro) is 13.9% larger for GPU-T at 4 lanes, but shrinks to within 3.7% of binary at 8 lanes, showing clear area convergence as word width increases.
